# 00. 要件整理（LPクリエイティブABテストツール）

> このドキュメントは、着手前の要件ヒアリングで確定した内容のサマリー。
> データモデルは [01-data-model.md](01-data-model.md)、アーキテクチャは
> [02-architecture.md](02-architecture.md)、既存の離脱防止ポップアップツール
> （以下「popup tool」）との連携仕様は [03-popup-integration.md](03-popup-integration.md) を参照。

## 1. 背景・目的

ECのLP（ランディングページ）クリエイティブ（画像）をA/B/C…と継続的にテストしたいが、
カートシステム上に新規クリエイティブを都度追加登録するのは運用負荷が高い。
カート側には一切手を入れず、**外部ツールがLP上の指定画像をブラウザ上で動的に差し替える**
ことで、無制限にクリエイティブパターンをテストできるようにする。

popup tool（離脱防止バナー配信）とは、タグ・アプリともに**完全に独立**したツールとして
構築する（詳細は 7 章）。

## 2. 差し替え方式（確定）

- LPにJSタグを1本設置する。カート側のHTML自体は変更しない
- ブラウザ上でタグが実行され、指定した画像要素（`src`が指定URLと一致するもの）を、
  配信ロジックが決定したパターンの画像URLに書き換える（クライアントサイド差し替え）
- 差し替え対象は**LPごとに最大2箇所**（スロットA・スロットB）
- 各スロットに入稿できるクリエイティブパターンは、**元画像を含めて最大99種**（3種を推奨値として画面に表示）
- スロットAとスロットBは独立して配信・集計される。両方を同時に持つLPでは、
  最大 A(99) × B(99) の組み合わせが理論上存在するが、レポートは基本的に
  スロット単体（Aの成績・Bの成績を別々に）で見る（4章参照）

## 3. LP管理（確定）

- LP登録項目：**品番・アイテム名・LP名・LPのURL（必須）**
- LP一覧は品番/アイテム名/LP名で絞り込み検索が可能。複数メンバー・複数アイテムでの利用を想定
- 配信停止中のLPは一覧でグレー表示、**デフォルト非表示**。表示条件の切り替えで表示可能
- 一覧の各行に▼があり、クリックでそのLPのアクティブなクリエイティブをアコーディオン表示
- LP一覧・レポートLP一覧には、LPのTOP画像（自動取得）をアイコン表示
- LPステータス表示（配信中 / 一部停止 / 全停止）をバッジ等で明示

## 4. クリエイティブ・表示率（確定）

- LP詳細画面で、既存LP上のクリエイティブプレビューと画像URLを並べて表示し、
  指定した画像URLを任意の画像に差し替え登録する
- クリエイティブには配信停止フラグがあり、いつでも停止・再開できる。**停止は最優先の操作**
  （自動最適化より常に優先。停止＝即時反映）
- 入稿時（新規パターン追加時）は、元画像を含めて**均等割り**。割り切れない端数は
  **常に元画像側に寄せる**（例：3パターンなら 33% / 33% / 34%、34%が元画像）
- そのスロットの入稿クリエイティブが全て停止状態になった場合は、**元画像100%配信に
  自動フォールバック**する。この間もレポート計測は継続する
- 表示率は手動でいつでも変更可能。加えて、**CVRベースの自動最適化**機能を持つ
  （5章）。クリック計測は行わないため、CTRは指標に含めない（imp / CVのみ）

## 5. 自動表示率最適化（確定）

- 評価指標は **CVR（imp→CVの転換率）のみ**（クリックは計測しないためCTRは使わない）
- **日次バッチ**で自動的に表示率を再配分する
- 反映条件：スロット/LPごとに設定可能な最低imp数・最低CV数の閾値を満たしたパターンのみ
  再配分対象にする（閾値未達のパターンは現状維持）。デフォルト値を持たせつつ管理画面で変更可能にする
- 下限フロア：各パターンに最低表示率を残す。**入稿パターン数に応じて動的に決まる下限**
  にする（固定%だと申請数が多い場合に合計が100%を超えてしまうため。例：均等割り時の
  割合を下回らない、または「最低◯imp/日は必ず回す」という基準）
- **自動反映後も、管理者・編集者はいつでも手動で表示率を上書き・固定できる**。
  手動固定したパターンは、次回の自動最適化実行時は対象から除外する（`locked`扱い）
- 自動最適化はスロットA・スロットBそれぞれ**独立**に実行する
- 配信停止フラグは自動最適化より常に優先する（停止中パターンへの配分は常に0）

## 6. レポート（確定）

- 計測イベントは **imp（LP表示時点）と CV のみ**。クリック・CTRは計測・表示しない
- デフォルト表示：当月配信実績のあるLPとクリエイティブが並ぶ
- 絞り込み：アイテム・期間・LPで絞り込み可能。期間指定で過去データも表示可能
- 基本のレポート単位は**スロット単体**（スロットAの3パターン、スロットBの3パターンを
  それぞれ別に集計）。必要に応じて **A×Bのクロス集計（最大9セル等）** に切り替え可能
- **統計的有意差フラグ**をレポートに表示する（サンプルサイズ・信頼度に基づく簡易判定）
- 表示中のレポート状態はいつでもCSVダウンロード可能
- **カレンダー式の変更履歴ビュー**：絞り込みメニューにアコーディオンで隠れているカレンダー
  検索があり、横軸＝日付・縦軸＝LP×クリエイティブの帯グラフを表示する。「帯」は日単位のセルで、
  同一構成（同じクリエイティブ構成）が連続する期間は自動でグルーピングされる。任意の帯を
  クリックすると、その期間にわたり実際に配信されていたクリエイティブ構成のみに絞ったレポートに
  遷移する。その後、アイテム等でさらに絞り込み可能
- ヒートマップ機能は**今回のスコープ外**（実装しない）

## 7. popup toolとの連携（確定）

- アプリ・タグとも**完全に独立**（同一LPでpopup tool未導入でも本ツール単体で運用できる）
- ログインは**共通化しない**（招待メールリストの母集団が同じだけで、それぞれのアプリに
  個別にGoogleアカウントでログインする。SSOは行わない）
- LP一覧・レポートLP一覧に、**popup toolアイコン**を表示し、以下にリンクする
  - LP一覧 → そのLPに対応するpopup tool側の**キャンペーン編集画面**
  - レポートLP一覧 → そのLPに対応するpopup tool側の**レポート画面**
  - 対応するキャンペーンが存在しない場合は**アイコン自体を表示しない**
  - 1つのURLに複数のpopup toolキャンペーンがマッチする場合は、
    popup tool側の**キャンペーン一覧ページ**へリンクする
- 連携はDB直結ではなく、popup tool側に追加する**軽量な参照用API**
  （`GET /api/v1/lookup?path=...`）をサーバー間で呼び出す方式（詳細は
  [03-popup-integration.md](03-popup-integration.md)）

## 8. 権限・ログイン（確定）

- 想定利用者は**社内（プライムダイレクト）専用**。外部クライアントへのSaaS提供は想定しない
- Supabase Auth（Google OAuth） + `@primedirect.jp` ドメイン限定 + 招待制
  （自己登録の入口はなし。管理者がメールアドレスを招待）
- 権限は3種類：

  | 権限 | 管理者 | 編集者 | 閲覧者 |
  | --- | --- | --- | --- |
  | LP / クリエイティブ登録・編集 | ○ | ○ | × |
  | 表示率変更・自動最適化結果の上書き | ○ | ○ | × |
  | メンバー招待・権限変更 | ○ | × | × |
  | レポート閲覧・CSVダウンロード | ○ | ○ | ○ |

## 9. 技術構成（確定）

- Supabase（Postgres + Auth + Storage） + Vercel（Next.js想定、popup toolと同スタック）
- popup toolとはSupabaseプロジェクトを分離し、必要な部分のみAPI経由で連携する
  （7章・[03-popup-integration.md](03-popup-integration.md)）

## 10. スコープ外（今回やらないこと）

- ヒートマップ（アテンション/スクロール/クリック）
- Slack通知
- クリック/CTRの計測
- popup toolとの完全SSO（ログイン統合）
