# 00. Phase 0 調査手順書（実装着手前にやること）

開発を始める前に、**3 つだけ**調べてほしいことがあります。
専門知識は不要です。ブラウザとスマレジ・リピートの管理画面があればできます。

| 調査 | 内容 | 所要 | 誰が |
| --- | --- | --- | --- |
| **A** | カート〜注文完了ページの**アドレス（URL）** | 5 分 | どなたでも |
| **B** | スマレジ・リピートの**差し込み変数の名前** | 10 分 | 管理画面が見られる方 |
| **C** | 商品ページの **URL と商品コード** | 3 分 | どなたでも |

いちばん重要なのは **調査 A** です。ここの結果で、システムの作り方が変わります。

**この文書の最後（6 章）に、そのままコピーして埋められる記入シート**があります。
埋めて返信いただければ、すぐ実装に入れます。

## 調査 A: カート〜注文完了ページの URL を調べる

### なぜ調べるのか

ブラウザには「**別のアドレスのページとは情報を共有できない**」という
セキュリティ上の決まりがあります。

```
www.primedirect.jp でバナーを見た人の情報
        ↓
   別のアドレス（例: cart.example.com）の注文完了ページ
        ↓
   「この人はバナーを見た人だ」と分からない ＝ 成果を計測できない
```

購入手続きの途中でアドレスが変わるかどうかで、**計測方法を変える必要がある**ため、
最初に確認します。変わっていても対応できますが、**作り方が変わります**。

### 手順

> ⚠️ 実際に注文を完了させる必要はありません。**手順 5 の手前まで**で
> ほとんどの情報が取れます（注文完了ページだけは 3.5 章の方法で確認します）。

#### 1. サイトを開く

パソコンのブラウザ（Chrome / Edge / Safari など）で
`https://www.primedirect.jp/` を開きます。

#### 2. 商品をカートに入れる

適当な商品を 1 つ選び、「カゴに入れる」を押します。

#### 3. 各画面で「アドレスバー」を見る

ブラウザの**いちばん上にある、アドレスが表示されている欄**です。

```
┌────────────────────────────────────────────┐
│  ←  →  ⟳   https://www.primedirect.jp/cart/ │  ← ここ
└────────────────────────────────────────────┘
```

**このアドレスを全部コピーして、メモ帳などに貼り付けてください。**

コピーの方法: アドレスバーを 1 回クリック → 全体が選択される →
`Ctrl + C`（Mac は `⌘ + C`）

#### 4. 次の画面に進むたびに、同じことを繰り返す

以下の各画面で、**そのつどアドレスをコピー**してメモしてください。

| # | 画面 | 画面の見た目の目印 |
| --- | --- | --- |
| ① | **カート画面** | 「ショッピングカート」「カートの中身」など |
| ② | **お客様情報の入力画面** | 氏名・住所・電話番号を入れる画面 |
| ③ | **お支払い方法の選択画面** | クレジットカード / 代引き などを選ぶ画面 |
| ④ | **注文内容の確認画面** | 「この内容で注文する」ボタンがある画面 |
| ⑤ | **ご注文完了画面** | 「ご注文ありがとうございました」の画面 |

> ④ の「注文する」ボタンは、押すと実際に注文が確定します。
> **⑤ を確認する方法は次の 3.5 章**を読んでから進めてください。

### 3.5 注文完了画面（⑤）の確認方法

⑤ だけは実際に注文しないと表示されません。次のいずれかで確認してください。

| 方法 | やり方 | 備考 |
| --- | --- | --- |
| **A. テスト注文機能を使う**（推奨） | スマレジ・リピートに「テスト注文」「テストモード」の機能があれば、それを使う | 課金なし。機能の有無は 4 章の質問文でサポートに確認できます |
| **B. 少額商品を実際に買う** | 最も安い商品を 1 つ、代金引換で注文 → 完了画面の URL をコピー → **すぐに電話でキャンセル** | 確実。社内の方が実施すれば問題になりません |
| **C. 過去の注文完了メールを見る** | 完了メールに完了ページへのリンクがあれば、そのアドレスを見る | 取れないことも多い |

**注文完了画面のアドレスが最重要**です。ここが計測の要になります。

### 判定（この結果で作り方が決まります）

メモした ①〜⑤ のアドレスを見比べてください。
見るのは `https://` の直後から、次の `/` までの部分です。

```
https://www.primedirect.jp/cart/
        └─────┬─────┘
          ここが「ホスト名」
```

| ①〜⑤ の結果 | 判定 | 意味 |
| --- | --- | --- |
| **全部 `www.primedirect.jp`** | 🟢 **パターンA** | 計測精度がいちばん高い構成。実装もシンプル |
| **途中から違う名前に変わる**<br>（例 `secure.〇〇.jp`、`〇〇.smaregi.jp` など） | 🟡 **パターンB** | 対応可能。ただし**「バナーを見ただけで買った人」の計測ができなくなります** |

#### 🟡 パターンB だった場合の追加確認（重要）

別のアドレスになっていた場合、**そのカート側に独自のアドレスを設定できないか**を
スマレジ・リピートのサポートに確認してください（4 章に質問文があります）。

例: `secure.smaregi-repeat.jp` → `cart.primedirect.jp` に変更できるか

**変更できれば パターンA と同じ精度になり、実装も簡単になります。**
確認する価値は十分にあります。

### スマートフォンでも同じ確認を

スマホ版で URL が違う場合があります（例: `sp.` が付く、`/sp/` が入る）。
スマホでも同じ手順で ①〜④ のアドレスを確認してください。

スマホでのアドレスの見方: 画面上部のアドレスバーをタップ → 長押し → 「コピー」

## 調査 B: 差し込み変数の名前を調べる

### なぜ調べるのか

注文完了ページに置くタグの中で、
「注文番号」「金額」といった**注文ごとに変わる値**を受け取る必要があります。

```html
<!-- 例: {{注文番号}} の部分に、実際の注文番号が自動で入る -->
orderId: '{{注文番号}}'      →      orderId: 'PD-20260811-0001'
```

この `{{注文番号}}` の部分に**何と書けばいいか**が、システムごとに違います。
スマレジ・リピートで決められた書き方を調べる必要があります。

### 手順

#### 1. スマレジ・リピートの管理画面にログイン

#### 2. 次のあたりのメニューを探す

システムによって名前が違うため、**以下のキーワードを含むメニュー**を探してください。

- 「**タグ**」「計測タグ」「広告タグ」「解析タグ」
- 「**サンクスページ**」「注文完了ページ」「完了画面」
- 「外部連携」「効果測定」「アクセス解析」
- 「デザイン設定」「ページ設定」「HTML 編集」

**設定 / システム設定 / ショップ設定** の配下にあることが多いです。

#### 3. 「使用できる変数の一覧」を見つける

タグを入力する欄の**近く**に、次のような案内があるはずです。

- 「使用可能な置換文字列」
- 「差し込みタグ一覧」
- 「利用できる変数」
- 「?」マークやリンクで開くヘルプ

そこに、こういった一覧が載っています（※表記はシステムにより異なります）。

```
%%order_no%%        注文番号
%%total_price%%     合計金額
%%order_type%%      注文区分
...
```

#### 4. 一覧をそのまま送ってください

**スクリーンショット（画面の写真）で構いません。**
一覧全体が写っていれば、こちらで必要なものを選びます。

スクリーンショットの撮り方:
- Windows: `Windows キー + Shift + S`
- Mac: `⌘ + Shift + 4`

### 特に必要な変数

| 用途 | 重要度 | 無いとどうなるか |
| --- | --- | --- |
| **注文番号** | 🔴 **必須** | 成果の計測ができません |
| 商品の合計金額 | 🟠 推奨 | 売上金額がレポートに出せません（件数は出ます） |
| 初回注文 / 継続注文の区別 | 🟠 推奨 | 定期の 2 回目以降も成果に混ざり、実際より多く見えます |
| 定期 / 都度 の区別 | 🟡 任意 | 分析の切り口が 1 つ減ります |
| 商品コード | 🟡 任意 | 注文側の商品別集計ができません |

### 見つからないときは（そのまま送れる質問文）

管理画面で見つからなければ、スマレジのサポートに以下をそのままお送りください。

```
お世話になっております。プライムダイレクトの〇〇です。

自社サイトの効果測定ツール導入にあたり、以下 5 点についてご教示ください。

1. ご注文完了（サンクス）ページに、任意の JavaScript タグを設置する
   設定画面の場所をお教えください。

2. そのタグ内で使用できる差し込み変数（置換文字列）の一覧をお教えください。
   特に以下の値を取得したいと考えております。
     ・注文番号
     ・商品の合計金額
     ・その注文が「初回」か「定期の2回目以降」かの区別
     ・定期購入か都度購入かの区別
     ・購入された商品コード

3. 定期購入の 2 回目以降の受注時にも、上記のタグは実行されますか。

4. カート・お客様情報入力・注文完了の各ページのドメイン（アドレス）は
   何になりますか。また、独自ドメイン（例: cart.primedirect.jp）を
   割り当てることは可能でしょうか。

5. 課金を発生させずに注文完了ページを確認できる
   テスト注文機能はございますか。

以上、よろしくお願いいたします。
```

## 調査 C: 商品ページの URL と商品コード

### 手順

1. `https://www.primedirect.jp/` で商品ページを **3 つ**開く
2. それぞれの**アドレスをコピー**してメモ
3. その商品の**商品コード**（管理画面や商品ページに表示されている品番）もメモ

```
例）
商品ページ: https://www.primedirect.jp/products/detail.php?product_id=123
商品名:     〇〇サプリ 定期コース
商品コード: PD-1001
```

### なぜ必要か

- ポップアップを「この商品ページにだけ出す」という設定に使います
- レポートを商品ごとに分けて見るための、名前合わせに使います

あわせて、**商品ページに商品コードを埋め込めるか**（テンプレートの編集ができるか、
商品コードを自動で差し込めるか）も分かれば教えてください。
分からなければ、こちらで商品ページの HTML を見て判断します。

## 5. FAQ

**Q. 実際に注文してしまって大丈夫ですか？**
A. 自社サイトなので問題ありません。代金引換で注文し、完了画面の URL を控えたあと
電話でキャンセルすれば費用も発生しません。テスト注文機能があればそちらが確実です。

**Q. 全部揃わないと開発を始められませんか？**
A. いいえ。**調査 A（特に注文完了画面の URL）さえ分かれば着手できます。**
B と C は開発と並行で構いません。

**Q. パターンB（別ドメイン）だと何ができなくなりますか？**
A. 「バナーを**クリックして**買った人」は計測できます。
「バナーを**見ただけ**（クリックせず）で、後から買った人」が計測できなくなります。
その分は、一部の人にわざとバナーを出さない「比較用グループ」を作って、
購入率の差から全体の効果を測ります（この仕組みは最初から組み込みます）。

**Q. 管理画面のメニュー名がこの文書と違います**
A. システムのバージョンで名称が変わります。3 章のキーワードで探して、
見つからなければサポートへの質問文をそのままお使いください。

**Q. 途中で分からなくなりました**
A. **その画面のスクリーンショットを送ってください。**
どこを見ればよいか、こちらから具体的にお伝えします。
