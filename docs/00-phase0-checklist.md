## ✅ 調査Dの結果（確認済み・さらに良い方法に変更）

いただいた「スマレジEC・受注API」の仕様書を確認しました。

## 調査 A: カート〜注文完了ページの URL を調べる（完了・参考情報）

> ✅ この調査はすでに完了しています。以下は「なぜこれを聞いていたか」の
> 背景説明です。同様の調査を別サイトで行う際にも使えます。

### なぜ調べるのか

ブラウザには「**別のアドレスのページとは情報を共有できない**」という
セキュリティ上の決まりがあります。

```
www.primedirect.jp でバナーを見た人の情報
        ↓
   別のアドレス（例: cart.example.com）の注文完了ページ
        ↓
   「この人はバナーを見た人だ」と分からない ＝ 成果を計測できない
```

購入手続きの途中でアドレスが変わるかどうかで、**計測方法を変える必要がある**ため、
最初に確認します。変わっていても対応できますが、**作り方が変わります**。

### 手順

> ⚠️ 実際に注文を完了させる必要はありません。**手順 5 の手前まで**で
> ほとんどの情報が取れます（注文完了ページだけは 3.5 章の方法で確認します）。

#### 1. サイトを開く

パソコンのブラウザ（Chrome / Edge / Safari など）で
`https://www.primedirect.jp/` を開きます。

#### 2. 商品をカートに入れる

適当な商品を 1 つ選び、「カゴに入れる」を押します。

#### 3. 各画面で「アドレスバー」を見る

ブラウザの**いちばん上にある、アドレスが表示されている欄**です。

```
┌────────────────────────────────────────────┐
│  ←  →  ⟳   https://www.primedirect.jp/cart/ │  ← ここ
└────────────────────────────────────────────┘
```

**このアドレスを全部コピーして、メモ帳などに貼り付けてください。**

コピーの方法: アドレスバーを 1 回クリック → 全体が選択される →
`Ctrl + C`（Mac は `⌘ + C`）

#### 4. 次の画面に進むたびに、同じことを繰り返す

以下の各画面で、**そのつどアドレスをコピー**してメモしてください。

| # | 画面 | 画面の見た目の目印 |
| --- | --- | --- |
| ① | **カート画面** | 「ショッピングカート」「カートの中身」など |
| ② | **お客様情報の入力画面** | 氏名・住所・電話番号を入れる画面 |
| ③ | **お支払い方法の選択画面** | クレジットカード / 代引き などを選ぶ画面 |
| ④ | **注文内容の確認画面** | 「この内容で注文する」ボタンがある画面 |
| ⑤ | **ご注文完了画面** | 「ご注文ありがとうございました」の画面 |

> ④ の「注文する」ボタンは、押すと実際に注文が確定します。
> **⑤ を確認する方法は次の 3.5 章**を読んでから進めてください。

### 3.5 注文完了画面（⑤）の確認方法

⑤ だけは実際に注文しないと表示されません。次のいずれかで確認してください。

| 方法 | やり方 | 備考 |
| --- | --- | --- |
| **A. テスト注文機能を使う**（推奨） | スマレジ・リピートに「テスト注文」「テストモード」の機能があれば、それを使う | 課金なし。機能の有無は 4 章の質問文でサポートに確認できます |
| **B. 少額商品を実際に買う** | 最も安い商品を 1 つ、代金引換で注文 → 完了画面の URL をコピー → **すぐに電話でキャンセル** | 確実。社内の方が実施すれば問題になりません |
| **C. 過去の注文完了メールを見る** | 完了メールに完了ページへのリンクがあれば、そのアドレスを見る | 取れないことも多い |

**注文完了画面のアドレスが最重要**です。ここが計測の要になります。

### 判定（この結果で作り方が決まります）

メモした ①〜⑤ のアドレスを見比べてください。
見るのは `https://` の直後から、次の `/` までの部分です。

```
https://www.primedirect.jp/cart/
        └─────┬─────┘
          ここが「ホスト名」
```

| ①〜⑤ の結果 | 判定 | 意味 |
| --- | --- | --- |
| **全部 `www.primedirect.jp`** | 🟢 **パターンA** | 計測精度がいちばん高い構成。実装もシンプル |
| **途中から違う名前に変わる**<br>（例 `secure.〇〇.jp`、`〇〇.smaregi.jp` など） | 🟡 **パターンB** | 対応可能。ただし**「バナーを見ただけで買った人」の計測ができなくなります** |

#### 🟡 パターンB だった場合の追加確認（重要）

別のアドレスになっていた場合、**そのカート側に独自のアドレスを設定できないか**を
スマレジ・リピートのサポートに確認してください（4 章に質問文があります）。

例: `secure.smaregi-repeat.jp` → `cart.primedirect.jp` に変更できるか

**変更できれば パターンA と同じ精度になり、実装も簡単になります。**
確認する価値は十分にあります。

### スマートフォンでも同じ確認を

スマホ版で URL が違う場合があります（例: `sp.` が付く、`/sp/` が入る）。
スマホでも同じ手順で ①〜④ のアドレスを確認してください。

スマホでのアドレスの見方: 画面上部のアドレスバーをタップ → 長押し → 「コピー」

## 調査 B: 受注APIのアクセストークンと、注文番号を出す差し込み変数

> 受注API（調査D）の仕様が分かったことで、商品コード・金額・初回/継続の判定は
> すべて**API側から自動取得**できるようになりました。そのため、サンクスページの
> タグに書いていただく差し込み変数は**「注文番号」1 つだけ**で十分です。
> 代わりに新しく必要になったのが**APIのアクセストークン**です。

### 必要なもの

| # | 項目 | 用途 | 重要度 |
| --- | --- | --- | --- |
| 1 | **APIアクセストークンの発行方法**（発行できる画面の場所） | 受注データを自動取得するために必須 | 🔴 必須 |
| 2 | サンクスページで「**EC注文番号**」を出力する差し込み変数の書き方 | サンクスページのタグに 1 つだけ書く値 | 🔴 必須 |
| 3 | `order.order_cnt`（購入回数）は「その顧客の通算注文回数」で合っているか | 初回注文かどうかの判定に使う | 🟠 推奨 |
| 4 | APIの呼び出し回数の上限（1分間・1日あたり） | どのくらいの頻度で確認しにいけるかの設計に使う | 🟡 任意 |
| 5 | 注文が完了してから、APIで確認できるようになるまでの時間差 | どのくらい待てば確実に反映されているかの目安 | 🟡 任意 |

### 手順

#### 1. アクセストークンの発行

スマレジECの管理画面で、**API・外部連携・開発者向け設定**といったメニューを探し、
「受注API」用のアクセストークンを発行してください
（すでにお送りいただいた仕様書に「受注API」の説明があったため、
発行できる画面もどこかにあるはずです）。

発行したトークンは**そのままメールやチャットで送っていただいて問題ありません**。
このツールのサーバー内だけで安全に保管し、画面には表示しません。

#### 2. サンクスページの差し込み変数

サンクスページの設定画面で、注文番号を出す差し込み変数を確認してください。
先の仕様書に基づくと、**「EC注文番号」**（`order.ec_order_id`）に対応する変数を
探していただくのが確実です。「注文番号」という名前の変数が複数種類ある場合は、
念のためすべて教えてください（こちらで正しいものを選びます）。

### 見つからないときは（そのまま送れる質問文）

```
お世話になっております。プライムダイレクトの〇〇です。

自社サイトの効果測定ツール導入にあたり、頂いた受注APIの仕様書をもとに
以下についてご教示ください。

1. 受注API（/api/v2/orders/search）用のアクセストークンは、
   どちらの画面で発行できますか。

2. ご注文完了（サンクス）ページに JavaScript タグを設置し、
   「EC注文番号」（order.ec_order_id に対応する値）を出力したいのですが、
   使用できる差し込み変数の名称をお教えください。

3. order.order_cnt（購入回数）は、その顧客の通算注文回数という
   理解で合っておりますでしょうか。この値が 1 の注文を
   「初回注文」として扱う想定です。

4. 受注APIの呼び出し回数に上限（レート制限）はございますか。

5. 注文完了から、受注APIで該当データを検索できるようになるまで、
   タイムラグはございますか。

以上、よろしくお願いいたします。
```

## 調査 C: 商品ページの URL と商品識別方法（完了・方針転換済み）

頂いた 2 件と、その後のご回答を反映しました。

```
https://www.primedirect.jp/products/pm100/   ← pm100 は商品コードではないとのこと
https://www.primedirect.jp/protein.html      ← LP（複数商品の紹介ページ）とのこと
```

### 分かったこと

商品ページの URL からは商品を正しく特定できないことが分かりました。
そのため、**商品ページに新しいタグを追加する方式はやめました。**

代わりに、**注文完了（サンクス）ページで受け取る「実際にカートに入った商品コード」**
だけを商品の正として扱う方針にしました（その後、調査 D の結果によりさらに、
受注APIから直接取得する形に確定しています）。

### この方針転換で何が変わったか

- 商品ページへのタグ設置作業が**不要**になりました
- 「どのページを見たか」（imp・クリック数）と「何が売れたか」（商品別の実績）は、
  別々の表としてレポートに出ます（同じ表では混ぜません）
- ポップアップを「特定の商品ページにだけ出す」設定は、
  URL のアドレスのパターン（例: `/products/` で始まるページすべて）で行います

## 5. FAQ

**Q. 実際に注文してしまって大丈夫ですか？**
A. 自社サイトなので問題ありません。代金引換で注文し、完了画面の URL を控えたあと
電話でキャンセルすれば費用も発生しません。テスト注文機能があればそちらが確実です。

**Q. 全部揃わないと開発を始められませんか？**
A. いいえ。**調査 A・C・D は完了しており、着手できる状態です。**
残る調査 B（APIトークンと注文番号の変数名）は開発と並行で構いません。

**Q. パターンB（別ドメイン）だと何ができなくなりますか？**
A. 「バナーを**クリックして**買った人」は計測できます。
「バナーを**見ただけ**（クリックせず）で、後から買った人」が計測できなくなります。
その分は、一部の人にわざとバナーを出さない「比較用グループ」を作って、
購入率の差から全体の効果を測ります（この仕組みは最初から組み込みます）。

**Q. 管理画面のメニュー名がこの文書と違います**
A. システムのバージョンで名称が変わります。3 章のキーワードで探して、
見つからなければサポートへの質問文をそのままお使いください。

**Q. 途中で分からなくなりました**
A. **その画面のスクリーンショットを送ってください。**
どこを見ればよいか、こちらから具体的にお伝えします。
